# Tables

Import components from `@axclogo/uikit/table` and load `@axclogo/uikit/table/styles.css` once. For the analysis condition editor, also load `@axclogo/uikit/condition/styles.css`. Locales and key types are available at `@axclogo/uikit/table/core`. The [entry reference](api/index.api.md) gives the TypeScript signatures.

## Composition

| Component         | Input and responsibility                                                                                                                                            |
| ----------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| BaseTable         | Stable row keys, rows or groups, render columns, selection, intrinsic action widths, fixed columns, resize, variable-height virtualization and pointer drop events. |
| DataTable         | Adapts field columns to BaseTable. Display precedence is render, formatter, registered or built-in type.                                                            |
| DataTreeTable     | Adapts an explicit child accessor to the same engine. Owns the visible preorder, indentation, expansion, child counts and move calculation.                         |
| DataAnalysisTable | Uses the shared table engine with a controlled view, search, condition draft, sort, column settings, coloring, pagination and saved-view slots.                     |
| DataCrudTable     | Composes DataTable with controlled keyword and filter values, explicit filters, toolbar slots, pagination and same-page reorder.                                    |
| TableUIProvider   | Supplies locale, native control replacements, confirmation, action errors, temporal formatters and custom cell types.                                               |

```tsx
import { DataTable, type DataTableProps } from '@axclogo/uikit/table';
import '@axclogo/uikit/table/styles.css';

type Item = { id: number; title: string };
const props: DataTableProps<Item> = {
	rows: [{ id: 0, title: 'First item' }],
	rowKey: 'id',
	columns: [{ key: 'title', title: 'Title', type: 'text' }],
	selection: { defaultSelectedRowKeys: [] },
};
export const Items = () => <DataTable {...props} />;
```

A row key is a key-valued property or a function of the record. Supply it on every table, including display-only tables. Width adjustment itself uses column keys. Numbers and strings retain their identity. Page selection adds or removes only selectable visible keys. Selecting A and B on page one and C on page two emits A, B and C. The batch context receives all three keys, count three, and only the selected records available on the current page. Clearing selection is an explicit action. In a tree, collapsing a branch preserves its selected keys.

`rows` and `groups` are exclusive. Use `fillHeight` with a bounded parent or set `height` directly. If both are omitted, components that accept `style` preserve its CSS height. Controlled selection and expansion exclude their initial values. Resizing previews locally, clamps pointer movement to the declared bounds and emits one final business-column width map. Drag callbacks describe a proposed move. A rejected drop leaves the input rows intact. Tree moves also expose the next parent, depth and sibling index; self, descendant, no-op and excessive subtree depth are invalid targets.

Analysis has two independent catalogs. All columns participate in column settings. All fields participate in capability lookup, including fields without a rendered column. The filter catalog uses `conditionable`; sorting uses `sortable`. Fields marked `colorable` or `conditionable` can drive row coloring. An empty visible list displays the full column catalog. The column picker lists every column in display order. Toggle its eye to show or hide it. Drag a grip to a new position, or focus the grip and use the Up and Down arrow keys. Hidden columns keep their position. Show all columns preserves the chosen order. At least one column stays visible when the catalog has entries. Hiding a column changes only its rendering. Apply a validated condition draft as `{query}`, an empty, non-negated root as `null`; cancel discards the draft. Submit-mode search commits on Enter or Search. Change-mode search commits on edit. Saved views, requests and pagination resets belong to the host.

CRUD search submits the trimmed keyword. Reset clears the keyword and filter values through their controlled callbacks before invoking the host reset callback. CRUD filters have their own keys. Select filters supply options, custom filters receive the current value and a change callback. A host can adapt a specialized value or parser there. Dates and datetimes require a provider formatter. Built-in cell types are text, number, boolean, json, date and datetime. A custom type requires a registered renderer. Convert application-specific field aliases and display labels to the declared field values before applying color rules. An action may be synchronous or asynchronous. Canceled confirmation skips execution. A thrown or rejected action reaches the supplied error handler with the original error.

Open **Color rules**, select a field and value, and choose a swatch. **Confirm** applies the completed rule and closes the dialog. **Add** keeps it open for another rule. Edit or remove existing rules in the same list. Pass the updated configuration back through `onConfigChange`. Each row uses the first matching rule in list order, including its pinned cells. Swatches and rows share the `--axc-table-red`, `--axc-table-orange`, `--axc-table-green`, `--axc-table-blue` and `--axc-table-grey` theme values.

Color rules read the matching column’s declared `dataIndex` if supplied, otherwise the named field on the row. They compare values as text. For a multi-value field, equality and substring rules match any item. Inequality matches when no item equals the rule value. Hiding a field’s column preserves its color rules.

## Interactive CRUD example

Run `npm run dev` and open [Table · CRUD](http://127.0.0.1:5178/#table-crud). Create a document, edit its title, drag rows, or select records on different pages and confirm their deletion. The example keeps data in memory.

Use `primaryActions` for creation and `actions` for row commands. The application owns the form, validation, persistence and the resulting rows. Return the mutation promise from an action to disable its button until completion. Confirmation preserves the target that was presented. A rejected action or confirmation reaches the configured `onActionError` callback. Refresh also disables its button while its promise is pending and forwards failures to the handler when supplied.

## Configuration and styling contract

Configuration errors throw `TypeError` with the offending property, value and expectation. Validate missing, invalid or duplicate row keys; duplicate or reserved column keys (`__selection`, `__drag`, `__actions`); incompatible row sources, dimensions or state modes; missing fixed widths and non-positive, non-finite or out-of-range widths. Validate density, drop positions, row height, selection/drag width, invalid children, unregistered types and missing temporal formatters. Duplicate analysis fields, unknown data types, enum fields without options, duplicate/unknown CRUD filters, select filters without options and custom filters without renderers are errors. Declaring row or batch actions requires an error handler. Empty data, off-page keys and a rejected drop are valid.

Import one stylesheet. The root and modifiers are `.axc-table`, `.axc-table-tree`, `.axc-table-analysis` and `.axc-table-crud`; theme values use `--axc-table-*`. Provide a bounded parent for fill height, commonly a flex child with `min-height: 0`. Browser acceptance covers sticky offsets, intrinsic action widths, drag geometry, variable-height scroll anchoring and density remeasurement.
