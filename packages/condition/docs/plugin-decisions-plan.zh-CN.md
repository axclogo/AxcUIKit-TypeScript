# 条件选择器与插件判断开发计划

本文是 UIKit 与 Eval 的联合开发方案。最终接口签名见插件模块的 API 参考。当前发布版的 AI 判断要求模型返回 `matched` 和 `reason`，后置条件可关闭。下文描述的是新的插件判断协议。

## 一、用户操作流程

1. 开发者选择应用开放的模式，注册自定义插件，并独立决定是否开启 AI 辅助编写。
2. 用户选择固定条件，或选择一个插件做判断。固定条件直接按既有规则求值。插件规则由可选前置条件、一个插件、必填后置条件构成。
3. 用户给插件配置输入和输出。后置条件选择器用来源标签区分原始字段和插件输出，支持同类型字段比较，也支持与固定值比较。
4. 用户可以选一条记录模拟，查看前置、插件、输出映射、后置各阶段的结果。规则可以保留为草稿，启用时必须通过完整校验。
5. 正式运行使用同一份规则和同一条执行路径。开发者可接留证回调，决定是否保存快照。

## 二、职责和协议

| 归属           | 交付内容                                                                                                                                     |
| -------------- | -------------------------------------------------------------------------------------------------------------------------------------------- |
| UIKit 条件组件 | 模式选择、规则配置、插件注册与接入状态、输入映射、结果预览、后置字段目录、模拟界面和 AI 辅助入口                                             |
| 插件           | 配置界面与校验、输入输出声明、独立于 React 界面的执行函数。测试和正式调用复用执行函数                                                        |
| Eval           | 配置与输出校验、前置求值、生成当次插件请求、JSONPath 取值、后置求值、执行轨迹和可选留证。规则比较与输出取值各有一个执行实现                  |
| 宿主           | 开放哪些模式，注入模型或脚本目录与调用接口、样本来源和可选 AI 生成服务，管理上传、权限、凭据和持久化。调度批量任务并关联每条记录的请求和结果 |

**规则保存什么。** 保存协议版本、前置条件、插件类型与配置、输入映射、输出定义及后置条件。模型和已有脚本使用外部标识及版本，代码块保存源码，HTTP 保存请求配置。测试响应、执行实例、回调、密钥和编辑器临时状态不进入规则协议。

**插件怎么接。** 公开一份带类型的插件契约，包含稳定类型标识、配置编辑器、配置校验、所需宿主接口和执行函数。执行函数接收配置、已映射的输入和取消信号，返回此次调用的结果；调用异常保留原始原因。自定义插件使用与预置插件相同的注册方式、输出映射和 AI 辅助能力。重复注册同一类型是配置错误。开发者决定开放范围，组件依据实际接口判断能否运行。打开已保存但当前未开放或未注册的插件规则时，保留原配置，指出缺少的类型或能力。

**一次调用怎么走。** Eval 先判断前置条件。跳过时结束；通过时返回当次请求，只包含插件所需的输入。应用的调度层按类型调用插件，插件直接执行或调用宿主。结果与同一次执行关联后交回 Eval，Eval 对照该次原始记录和声明的输出判断后置条件。并发时按请求关联结果，取消或切换样本后到达的旧结果不能覆盖当前预览。浏览器插件可在没有编辑界面的批量任务里运行；其他运行环境需要显式提供可用的执行实现。

## 三、五种预置插件

| 插件              | 用户配置与测试                                                                                        | 执行归属                                                                                                                        |
| ----------------- | ----------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------- |
| AI 大模型         | 选已有模型、写提示词、映射输入；可用原始 AI 文本判断关键词，也可从解析出的 JSON 定义输出              | 插件调用宿主提供的大模型接口                                                                                                    |
| 小模型            | 选模型及版本、映射入参；在底部只读 JSON 编辑器查看返回结果，下面定义 JSONPath 输出                    | 插件调用宿主的模型接口。上传、存储、加载和推理由外部负责                                                                        |
| JavaScript 代码块 | 直接在 Code Editor 编写 JS，配置入参、运行测试、查看返回的 JSON 并定义输出                            | 预置浏览器执行函数，使用可终止的 Worker。只支持 JS，不引入编译器。Worker 用于隔离主线程，运行不受信任源码的部署另行提供安全隔离 |
| HTTP              | 填方法、URL、查询参数、Headers、Body；测试后先展示只读 Response JSON，再配置输出 key、JSONPath 和类型 | 预置浏览器请求函数，遵守浏览器跨域限制。需要私密凭据的接口由宿主在服务端处理                                                    |
| 已有脚本          | 从目录选择脚本及版本，映射输入，预览返回的 JSON 并定义输出                                            | 插件调用宿主的脚本接口                                                                                                          |

小模型和脚本选择器提供操作位。宿主可在这里放上传或登记按钮；操作完成后刷新受控目录即可选择新项目。接口未接、接口已接但目录为空、实际调用失败要分别展示。模式已开放但缺必要接口时显示具体缺项，禁用相应测试操作；正式运行遇到同一情况返回配置错误。

HTTP 新配置至少成功测试一次才能作为可运行规则保存。修改请求配置或其输入映射后重新测试；只改输出 key、路径或类型时，用当前测试响应就地验证。测试使用真实请求，展示请求失败、非成功状态、非 JSON 响应或映射错误，不把它们当作测试通过。配置页的测试记录与可执行规则分开；正式执行始终取当次响应。

## 四、后置条件与 JSONPath

例：记录中有 `id` 和数值 `minScore = 80`，只把 `id` 发给 HTTP 插件。响应为 `{"data":{"score":86,"active":true}}`。

| 输出 key | JSONPath        | 声明类型 | 测试预览 |
| -------- | --------------- | -------- | -------- |
| score    | `$.data.score`  | 数字     | 86       |
| active   | `$.data.active` | 布尔     | true     |

后置可写「插件输出 / score ≥ 原始数据 / minScore」并且「插件输出 / active 等于 true」。同名字段按来源区分。模拟时能看到实际比较的是 86 和 80。固定条件、前置和后置沿用已有条件运算符，插件输出字段要支持右侧选择同类型字段。

- 预览和执行复用 Eval 的提取接口。第一版建议明确支持根、对象键和数组下标等单值路径；在协议阶段列出精确语法及合法示例。不支持的语法、重复输出 key、必需路径缺失、返回多值与声明不符、类型不符都定位到具体输出。区分缺失、JSON null、0、false 和空字符串。
- AI 原文始终作为字符串字段提供。如果完整原文能解析成 JSON，则同时提供 JSON 源；纯文本回复也是成功调用。没有 JSON 源时，JSONPath 输出记为缺失，仍允许原文关键词分支按照现有条件与短路语义求值。若要断言提取值存在，可在条件中显式配置。已有 JSON 源却配错路径，按映射错误处理。
- 修改输出 key、删除输出或更改其类型时，标出引用失效的后置条件，保留用户草稿；启用前必须修正。插件执行成功只代表拿到了结果。所有插件，包括 AI，都由后置条件给出最终判定。

## 五、可选的公共 AI 辅助编写能力

开发者独立选择是否启用 AI 辅助，并提供一次生成服务。不开启时，手写、测试、模拟和正式判断都照常使用。开放运行时 AI 插件与开启编辑期辅助是两个独立选项。

公开一个可在自定义插件编辑器中使用的辅助入口。每个入口声明**生成目标、当次允许使用的上下文、如何解析候选、采用后回填哪里**。基座负责发起请求、取消、失效处理、展示错误和预览。用户点「采用」才回填，采用不会自动保存、调用 HTTP 或执行代码。

| 使用位置           | 提供给辅助的上下文                     | 采用后的目标           |
| ------------------ | -------------------------------------- | ---------------------- |
| 固定条件、前置条件 | 可用原始字段、类型、运算符、当前草稿   | 经条件协议校验的条件树 |
| 后置条件           | 原始字段、插件输出字段、类型、当前草稿 | 可比较两种来源的条件树 |
| AI 插件提示词      | 已选输入、预期输出、当前提示词         | 当前提示词框           |
| JS 代码块          | 入参名与类型、预期输出、当前源码       | 当前源码编辑器         |
| 第三方插件         | 插件声明的上下文与候选解析器           | 插件自己的配置字段     |

第三方接入示例必须演示：在自定义编辑器里给某个文本框加「帮我写」，复用宿主已配置的生成服务；取消时保留原文，采用时只更新这个字段。默认只给生成任务所需的字段定义与草稿，不自动附带样本记录、响应正文或请求凭据。对生成服务的错误与候选格式错误分别反馈。

## 六、开发顺序与验收门槛

| 阶段              | 开发任务                                                                                                       | 通过标准                                                                                                                                         |
| ----------------- | -------------------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------ |
| 0. 基线与协议草案 | 跑两仓现有检查，盘点固定条件、已发布 AI 协议、模拟与留证。给出新规则、请求、响应、字段来源、错误和插件接口草案 | 同一批样例覆盖五种插件、原文关键词与跨字段比较；明确旧规则的迁移方式、JSONPath 范围和运行环境                                                    |
| 1. Eval 核心      | 在 Rust 实现插件前置与完成结果两阶段、映射与强类型校验、后置求值、轨迹和证据；导出浏览器 WASM 与 Python 绑定   | 同一组协议夹具在各入口的结果、错误路径和短路轨迹一致；固定条件原有夹具通过                                                                       |
| 2. UIKit 插件基座 | 实现受控模式与注册、依赖状态、三段编辑、区分来源的字段目录、公共结果预览和输出映射 UI                          | 用一个最小自定义插件跑通编辑、保存、再打开和模拟；不靠修改组件核心接入                                                                           |
| 3. 五种预置插件   | 先用 HTTP 和 JS 走通直接执行，再接小模型、已有脚本及 AI 的宿主调用；按需加载编辑器与 Worker                    | 每个插件都能正常测试、反馈错误并用于后置判断；只开固定条件时不加载插件运行时                                                                     |
| 4. 通用 AI 辅助   | 从现有辅助面板提取公共生成、预览、取消与采用流程，接入条件、提示词、源码及第三方编辑器                         | 开关独立；过期响应不回填；结构化草稿校验失败不能采用；自定义插件复用同一个入口                                                                   |
| 5. 模拟与留证     | 单条真实运行、显式使用样例输出验证后置、批量乱序与取消、可选外部证据回调                                       | 能指出是前置跳过、插件失败、映射失败、后置未命中或命中。模拟标明结果来源；留证记录当次规则、关联标识、输入、结果或错误；宿主决定脱敏、存储和留存 |
| 6. 文档与终验     | 更新中英文使用指南、接口参考、迁移说明和统一示例页；演示五种预置、一个第三方插件及其辅助入口                   | 新接入者能按文档完成接入；浏览器可直接操作验收；完整质量门禁通过后交用户终验                                                                     |

已发布 AI 协议与新协议语义不同。迁移设计须明确旧规则中的 `matched` 门槛、`reason` 以及可空后置条件如何处理；无法等价表达的规则列出并交用户确认。运行时按显式协议识别规则，禁止猜测格式或静默改写判定结果。

每个实现阶段在变更仓库跑完整门禁。UIKit 使用 `npm run verify`，覆盖 React 18/19、协议、类型、API 漂移和体积。Eval 使用仓库 CI 的 Rust、覆盖率、WASM/npm 和 Python 检查，新路径补充成功、非法输出及外部调用失败的用例。跨仓阶段对照同一批夹具。浏览器终验覆盖 HTTP 成功与失败、Worker 超时与取消、两条记录乱序完成、纯文本 AI 命中关键词、缺少宿主接口与辅助关闭。测试使用可控模型回调，不依赖付费模型效果。

实现入口为 `@axclogo/uikit/decision-plugins`，具体接口以该模块中英文 README 和 API 参考为准。固定条件继续使用 `condition` 入口；旧 decision 协议独立保留，不参与新插件运行路径。提交和发布需另行授权。
